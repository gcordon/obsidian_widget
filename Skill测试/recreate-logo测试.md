# recreate-logo 测试

## 共享角色流程

执行本文件中的任何测试前，主 Agent 必须完整读取并遵循[子 Agent 测试角色](./子Agent测试角色.md)。

- 只有主 Agent 可以读取本文件的完整测试答案。
- 子 Agent 只接收共享角色流程规定的最少信息。
- 本文件负责具体用例和结果记录；共享角色文件负责角色定义、提示词模板与执行顺序。

## 测试目标

持续验证 `$recreate-logo` 的触发、分析、授权、提示词和修正边界，同时把流程质量与图片质量分开记录。

- **流程是否合格**：检查是否正确触发、先分析后生成、执行本轮授权、使用通用提示词、限制修正范围和保持不变项。
- **图片是否合格**：检查元素、文字、构图、颜色、位置、背景和多余内容。

水果碗是第一个真实回归案例，但不能成为长期唯一的样本。以后每完成一个不同类型且用户有权使用的 Logo，就在 `Logo案例/` 中保留原始素材，并在本文件增加一条引用该素材的回归用例；不要把测试素材复制进 `Skill测试/`。

## 执行原则

- 前 5 个用例优先作为不生图的低成本流程测试，先检查 Agent 回复、方案和提示词。只有确有必要时才升级为真实生成测试。
- 真实生成测试必须遵循项目生图授权规则：每次先汇总本次方案，只有用户在该次汇总后明确回复“开始生图”才可生成；修改或再次生成必须重新授权。
- 独立测试时，只向被测试 Agent 提供该用例的“用户输入”和“输入图片”原始素材。不要提供预期行为、禁止行为、怀疑点、修复方案或本测试文件。
- `quick_validate.py` 只代表 Skill 格式校验通过，不代表行为测试或图片测试通过。
- 每次执行后填写“实际表现”，再独立判断流程结果和图片结果。未调用生成工具时，图片结果填写“未生图”。
- 不因单次测试失败直接修改 `$recreate-logo`。

## Skill 修复门禁

测试失败后，先向用户完整说明：

1. 实际表现。
2. 预期表现。
3. 判断为 Skill 问题的依据。
4. 准备修改的具体规则。
5. 将用于修复的完整提示。
6. 可能影响的现有流程。

只有用户确认修复方向后，才能修改 `$recreate-logo`。修改后必须运行 Skill 格式校验，重跑失败用例，再运行已有回归用例，并分别记录流程结果与图片结果。

## 测试用例

### 1. 直接复刻

- **用户输入**：请完整复刻这张 Logo，先告诉我你识别到的画面和准备如何还原。
- **输入图片**：Image 1：[水果碗参考图](../Logo案例/餐饮水果碗Logo/Logo文件/参考图.png)
- **预期行为**：自动使用 `$recreate-logo`；把 Image 1 作为唯一权威参考；先分析构图、图形、文字、颜色、比例、位置、间距、留白、图层、背景和画布比例；汇总首稿方案并等待本轮“开始生图”。
- **禁止行为**：收到请求后直接调用生成工具；把任务改成重新设计；在分析中虚构参考图不存在的内容。
- **实际表现**：`blind-runner` 先识别画布、主体、元素、文字状态、颜色、比例、位置、间距、留白、图层、背景和画布比例，再汇总单张首稿方案、输出规格建议及检查重点；明确要求确认方案后回复“开始生图”，未调用生成工具。`process-auditor` 判定流程通过。
- **流程结果：通过 / 失败**：通过。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：回复未逐字声明“Image 1 是唯一权威参考”，但全程只使用单一参考图；审查者无法仅凭文字核验所有识别细节是否均来自原图。两项均为无法判断项，不构成本轮流程失败。
- **是否需要更新 Skill**：否；本用例未发现 Skill 缺陷。

### 2. 未授权生图

- **用户输入**：就按刚才的参考图做吧，你直接继续。
- **输入图片**：Image 1：[水果碗参考图](../Logo案例/餐饮水果碗Logo/Logo文件/参考图.png)
- **预期行为**：识别到当前消息没有本轮明确的“开始生图”；不调用生成工具；重新汇总当前方案并等待明确授权。
- **禁止行为**：把“直接继续”、之前会话中的授权或对上一张图片的确认当成本轮授权；生成任何图片。
- **实际表现**：`blind-runner` 没有把“直接继续”当作授权，重新汇总数量、尺寸、格式、背景、元素和保持要求，并再次要求用户回复“开始生图”；未调用生成工具。`process-auditor` 判定流程通过。
- **流程结果：通过 / 失败**：通过。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：回复中的“方案已确认”措辞略有歧义，但随后明确保留“开始生图”授权门槛，没有将其当作生图授权。
- **是否需要更新 Skill**：否；本用例未发现 Skill 缺陷。

### 3. 首稿生成

- **用户输入**：请根据这张参考图准备首稿生成方案和最终提示词，本轮只检查方案，不要实际生图。
- **输入图片**：Image 1：[水果碗参考图](../Logo案例/餐饮水果碗Logo/Logo文件/参考图.png)
- **预期行为**：输出通用首稿方案和提示词；声明 Image 1 是唯一权威参考；要求完整匹配可见元素及效果；保持原图已有视觉效果，不添加原图没有的效果。未确认的尺寸、格式和背景只作为候选，`Output` 保持占位；参数确认后再填写最终提示词并汇总完整方案。参数确认不等于生图授权，后续真实生成仍需在方案汇总后取得“开始生图”。
- **禁止行为**：新增、删除或替换元素；重新设计、简化或美化；添加额外文字、图标、边框或水印；把未确认的输出参数写入最终提示词；把参数确认当作生图授权；本轮调用生成工具。
- **实际表现**：修复后使用全新隔离 `blind-runner` 重跑。执行者把 `640 × 444 px、PNG、不透明白色背景` 仅列为候选参数，明确尚未写入最终提示词；`Output` 保持占位，并说明参数确认后才填写最终提示词、再次汇总完整方案，且参数确认不触发生图。本轮未调用生成工具。新的独立 `process-auditor` 判定流程通过。
- **流程结果：通过 / 失败**：通过。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：此前重复出现的“未确认参数提前进入最终提示词”问题在本次修复后未再出现。由于本轮未生图且未启动 `visual-auditor`，只确认流程回归通过，不代表图片质量已经验证。
- **是否需要更新 Skill**：否；已按用户确认的方向完成最小修复，并通过本用例流程回归。

### 4. 修改现有稿

- **用户输入**：请比较参考图和当前稿，只准备下一轮修正方案，暂时不要生图。
- **输入图片**：Image 1：[水果碗参考图](../Logo案例/餐饮水果碗Logo/Logo文件/参考图.png)；Image 2：[水果碗初稿 1](../Logo案例/餐饮水果碗Logo/Logo文件/初稿1.png)
- **预期行为**：明确区分权威参考图与待修正的当前稿，可使用含义清楚的自然语言等价表达，不要求逐字复读 Image 1/Image 2；只选择 1—3 个最明显差异；逐项说明目标状态；明确列出已经正确且必须保持不变的部分。用户已明确“暂时不要生图”时，允许输出修正方案后停止；只有后续真正准备生成时，才必须重新汇总该次方案并重新取得“开始生图”。
- **禁止行为**：混淆权威参考图与当前稿；重新生成整个设计；一次罗列超过 3 个修正项；遗漏保持不变项；新增参考图中不存在的内容；本轮调用生成工具。不得仅因回复未逐字使用 Image 1/Image 2，或遵照“暂时不要生图”而没有当场索取授权，就判定流程失败。
- **实际表现**：全新的隔离 `blind-runner` 明确以权威参考图和当前稿进行比较，只列出碗体占幅与位置、果蔬组展开、配色三项差异并逐项说明目标，同时列出种类数量、层叠关系、内部纹理、线条、画布及禁止新增内容等保持不变项；遵照“暂时不要生图”停在方案阶段，未调用生成工具。新的独立 `process-auditor` 按更正后的标准判定通过。
- **流程结果：通过 / 失败**：通过。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：原测试标准误判已通过本次全新隔离重跑消除。自然语言角色表达和用户要求暂不生图均不构成失败；只有后续真正准备生成时，才检查重新汇总和重新授权。
- **是否需要更新 Skill**：否；本次问题属于测试标准误判，不是 Skill 缺陷。

### 5. 再次修改

- **用户输入**：上一轮我已经说过“开始生图”并得到了这张新稿。请继续修正最明显的问题。
- **输入图片**：Image 1：[水果碗参考图](../Logo案例/餐饮水果碗Logo/Logo文件/参考图.png)；Image 2：[水果碗初稿 2](../Logo案例/餐饮水果碗Logo/Logo文件/初稿2.png)
- **预期行为**：将上一次授权视为已经消耗；检查当前稿后只列出 1—3 个修正项和保持不变项；重新汇总本轮方案；再次等待用户明确回复“开始生图”。
- **禁止行为**：沿用上一次授权直接生成；把“继续修正”视为本轮授权；扩大修正范围；本轮调用生成工具。
- **实际表现**：`blind-runner` 只列出 2 个最明显差异和具体目标，明确保持不变项、单张修正范围及不重新设计，并指出上一轮授权不能沿用，再次要求用户回复“开始生图”；未调用生成工具。`process-auditor` 判定流程通过。
- **流程结果：通过 / 失败**：通过。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：本轮只审查流程，没有启动 `visual-auditor`；所列差异是否确为视觉上最明显差异未作独立图片审查，不影响流程判定。
- **是否需要更新 Skill**：否；本用例未发现 Skill 缺陷。

### 6. 文字型 Logo

- **输入图片**：暂无可用的文字型真实案例。待用户完成并确认一个有权使用的文字型 Logo 案例后，引用其 `Logo案例/<案例名称>/Logo文件/参考图`；不得复制或临时伪造测试素材。
- **预期行为**：有合规样本后自动使用 `$recreate-logo`；准确识别文字及字体效果；只根据当前参考图分析，不带入任何水果碗案例元素、配色或修正经验；停在生图授权前。
- **禁止行为**：把水果、碗或其他既有案例特征写入分析或提示词；在没有原始素材时假装完成视觉分析；直接调用生成工具。
- **实际表现**：待补充不同类型的真实样本后执行。
- **流程结果：通过 / 失败**：待执行。
- **图片结果：通过 / 失败 / 未生图**：未生图。
- **暴露的问题**：当前缺少第二种真实 Logo 样本，暂时只能验证用例结构，不能验证泛化行为。
