# AI Logo 练习原始档案归档设计

日期：2026-05-27

## 背景

当前 AI Logo 学习流程里，ChatGPT 网页版负责生成和回复，Codex 负责本地落盘和整理，Obsidian 负责长期保存。

这次「饭团小满」练习暴露出一个问题：用户的提问、GPT 的回复文字和 GPT 生成图片不能只临时放在 `GPT_lt` 这类目录里，否则后续很难追踪一次练习的完整历史。

## 核心目标

为每次 AI Logo 练习建立一个原始档案包，先完整保存本次练习的输入、输出和素材，再由 Codex 后续整理到 Daily、案例库、Prompt 库和图片资产目录。

## 推荐位置

原始档案统一放在：

```text
AI_LOGO_Obsidian_学习库_StarterVault_v5/00_Inbox/练习原始记录/
```

单次练习使用：

```text
YYYY-MM-DD_品牌名_方法名/
```

本次示例：

```text
00_Inbox/练习原始记录/2026-05-27_饭团小满_直接生成/
```

## 单次练习目录结构

```text
2026-05-27_饭团小满_直接生成/
├── 00_你的提问.md
├── 01_GPT回复_待你粘贴.md
├── images/
│   └── 这里放你手动保存的 GPT 图片
└── README_整理说明.md
```

## 职责分工

Codex 负责：

- 自动创建本次练习文件夹。
- 自动写入 `00_你的提问.md`。
- 自动创建 `01_GPT回复_待你粘贴.md`，并留下粘贴位置。
- 自动创建 `images/` 文件夹。
- 自动创建 `README_整理说明.md`，说明用户下一步怎么补材料。
- 后续根据用户补充内容整理到 `01_Daily`、`40_Cases`、`30_Prompts` 和 `80_Assets`。

用户负责：

- 把 ChatGPT 网页版的回复文字粘贴到 `01_GPT回复_待你粘贴.md`。
- 把 ChatGPT 生成的图片手动放进 `images/`。
- 回到 Codex 对话里说明材料已经补齐，或者继续描述图片问题。

## 后续整理规则

当用户补齐 GPT 回复和图片后，Codex 再执行长期整理：

- Daily：把当天练习目标、结果判断和学习收获写入 `01_Daily`。
- Cases：把完整复盘沉淀到 `40_Cases`。
- Prompts：把有效 Prompt 或方法模板沉淀到 `30_Prompts`。
- Assets：把值得保留的生成图复制或移动到 `80_Assets/02_Generated`，最终版放到 `80_Assets/03_Final`。

原始档案包不删除，用作历史证据和学习回溯。

## 命名规则

练习目录：

```text
YYYY-MM-DD_品牌名_方法名
```

图片读取规则：

- 如果 `images/` 里只有一张图片，Codex 默认把它当作本次 `generated_v01`，不要求用户额外改名。
- 如果 `images/` 里有多张图片，用户需要特别命名，或让 Codex 按版本顺序整理。

多张生成图片建议用户手动命名为：

```text
YYYY-MM-DD_品牌名_generated_v01.png
YYYY-MM-DD_品牌名_generated_v02.png
YYYY-MM-DD_品牌名_final_logo.png
```

如果用户暂时没有重命名图片，Codex 后续整理时可以协助统一命名。

## 非目标

本设计当前不做：

- 不把原始 GPT 回复直接混入正式案例库。
- 不要求用户每天手动维护多个 Obsidian 页面。
- 不强制用户先整理图片命名再继续练习。
- 不把 `GPT_lt` 作为长期目录。
- 不改变现有 `80_Assets` 的资产分类规则。

## 验收标准

一次练习开始后，应能快速确认：

1. 本次练习的原始问题保存在哪里。
2. GPT 回复文字应该粘贴到哪里。
3. GPT 生成图片应该放到哪里。
4. 后续 Codex 能从一个文件夹读到完整练习历史。
5. 临时目录不再承担长期保存职责。

## 本次实施对象

本次先创建：

```text
AI_LOGO_Obsidian_学习库_StarterVault_v5/00_Inbox/练习原始记录/2026-05-27_饭团小满_直接生成/
```

其中 `00_你的提问.md` 写入用户实际发送给 GPT 的提问；`01_GPT回复_待你粘贴.md` 和 `images/` 等待用户补充。
