# Recreate Logo

## 执行原则

- 顶层任务模式只有复刻和二次开发；修正是两种模式共用的质量返工循环，不是第三种模式。
- 复刻不得重新设计；二次开发只改变用户授权的内容。
- 生成稿只能作为待检查或待修正的当前稿。
- 优先交付简单、合格、可检查的结果，再根据真实差异逐轮修正。
- 不把任何单一案例的图形、文字、颜色或特殊轮廓写入通用流程。
- 只在 `references/` 维护 Prompt 正文；`SKILL.md` 只保存读取条件和执行流程，不重复 Prompt 正文。
- 图片分析和需求整理时，同时加载并遵循 `imagegen` Skill。
- 图片生成统一使用 `gpt-image-2`。
- 一次只生成一张 Logo；未经授权不得调用图片生成工具。

## 任务模式判定

在讨论生图方案前，根据输出资产身份记录以下字段：

1. 输出资产身份：本次结果代表的 Logo、品牌、版式或用途。
2. 根权威参考：控制来源身份和视觉语言的最初参考。
3. 直接父资产：控制现有版式和可继承内容的已有资产；首次复刻可为空。
4. 用户变更规格：控制新内容和允许变化范围的已确认要求。
5. 顶层模式：同一参考 Logo 的首次还原为复刻；继承已有资产部分特征并形成新文字、品牌、版式或用途资产为二次开发。

当前稿与确认目标存在差异时，进入所属模式的修正循环，不改变顶层模式。

## 源资产预检

开始预检前，检查项目 [已知失败与恢复工作台](../../../项目规范/已知失败与恢复/已知失败与恢复工作台.md)。需要精确继承已有资产时，加载 [IMG-001](../../../项目规范/已知失败与恢复/IMG-001-精确不变量偏差后继续全图生成修正.md)。

1. 检查实际输入的尺寸、清晰度、构图和背景是否满足已确认目标。
2. 满足要求时直接使用该资产，不为统一尺寸或形式重新生成。
3. 不满足要求时只提出必要变换，并在生图前重新获得本次方案授权。
4. 派生输出使用新文件或新版本，不得覆盖直接父资产。

## 精确不变量

1. 对需要精确继承的二次开发，在生图方案中分别记录授权编辑区域和锁定属性；未授权区域视为锁定区域。
2. 用户要求精确继承时，把画布、背景、有限调色板、整体前景边界、元素位置、尺寸和间距视为可确定验证的不变量。
3. 在最终提示词中要求新内容限制在直接父资产的对应区域内，不得重新生成锁定背景，不得缩放、重排或重绘锁定内容。
4. 生成后对可测量的精确不变量进行直接父资产对照，不以目测通过替代可取得的尺寸、位置或颜色证据。
5. 该类失败的后续动作统一执行 [IMG-001](../../../项目规范/已知失败与恢复/IMG-001-精确不变量偏差后继续全图生成修正.md)；本 Skill 不重复条目正文。
6. 确定性后处理或局部编辑必须生成新文件或新版本，并记录实际输入、工具、命令或参数、输出规格、SHA-256 和验证结果。

## 生图前确认

在每次调用图片生成工具前执行以下步骤：

1. 与用户讨论本次目标、输出尺寸、格式、背景以及画面结构。
2. 只有用户明确确认的尺寸、格式和背景才能写入最终提示词；未确认的参数只作为候选方案向用户询问。
3. 参数确认后，填写最终提示词并汇总本次调用的完整生图方案。若涉及多张图片，分别说明每张图片的方案，但每次工具调用仍只生成一张 Logo。
4. 参数确认不等于生图授权。只有用户在该次完整方案汇总后明确回复“开始生图”，才调用生成工具。
5. 只把授权用于该次已汇总的方案。新增、修改或再次生成图片时，重新汇总方案并重新获得“开始生图”授权。

不得把用户更早的授权、宽泛的“继续”或对上一张图片的确认视为本次生图授权。

## 复刻首稿提示词

准备首稿时，完整读取并使用 [首稿 Prompt](./references/首稿Prompt.md)。

只有用户明确确认的尺寸、格式和背景才能替换 `Output` 占位；未确认时保持占位，只提出候选方案并等待确认。不要加入案例之外的创意指令。

## 二次开发提示词

准备二次开发首稿时，完整读取并使用 [二次开发 Prompt](./references/二次开发Prompt.md)。

根权威参考控制来源与视觉语言，直接父资产控制现有版式与可继承内容，用户确认的变更规格控制新内容。只有用户确认的改变项才能写入最终提示词。

## 通用修正提示词

准备任一模式的修正稿时，完整读取并使用 [修正 Prompt](./references/修正Prompt.md)，按当前模式填写适用的权威资产和用户确认目标。

通用修正 Prompt 只适用于非精确不变量的普通视觉差异。进入该 Prompt 前先按 [IMG-001](../../../项目规范/已知失败与恢复/IMG-001-精确不变量偏差后继续全图生成修正.md) 完成分流。

每轮只填写 1—3 个高优先级差异，并明确列出保持不变项。修改前重新执行“生图前确认”。

## 基础验收清单

按当前模式对照适用的权威资产和用户确认目标检查当前稿，仅检查以下必要项目：

- 元素是否完整
- 文字是否逐字准确
- 构图和比例是否匹配
- 颜色和视觉效果是否一致
- 位置和间距是否合理
- 背景和画布比例是否匹配
- 是否出现多余内容

验收后只选择最明显的 1—3 个差异进入下一轮，不提出无关创意建议。

## 标准执行步骤

1. 接收用户拥有或获准使用的参考 Logo 或已有资产，并确认本次输出要求。
2. 判定复刻或二次开发模式，记录输出资产身份和对应权威关系。
3. 使用 `imagegen` Skill 分析输入和整理需求，不先生成图片。
4. 执行源资产预检；合格资产直接使用，不重新生成。
5. 按模式读取复刻首稿或二次开发 Prompt，提出候选输出参数并等待用户确认。
6. 填写最终提示词、汇总完整生图方案，再等待用户回复“开始生图”。
7. 获得本次授权后，使用 `gpt-image-2` 生成一张首稿。
8. 按基础验收清单找出最明显的 1—3 个差异。
9. 区分精确不变量偏差和其他视觉偏差。
10. 第 9 步判定为精确不变量偏差时，转入 [IMG-001](../../../项目规范/已知失败与恢复/IMG-001-精确不变量偏差后继续全图生成修正.md)。
11. 其他视觉偏差使用通用修正提示词列出修正项和保持不变项，重新汇总方案并重新等待“开始生图”。
12. 每次只生成或处理一张修正稿，重复验收与授权流程，直到用户确认成品。
13. 保存用户确认的成品；不要再用模型重新生成已确认的主文件。
14. 按项目 [资产溯源与派生血缘规范](../../../项目规范/资产管理/资产溯源与派生血缘.md) 归档根权威参考、直接输入、输出、实际 Prompt、执行 ID、变换、规格、哈希和验证生命周期。
15. 实际调用 Prompt 放入案例 `Prompt/`；案例工作台只保留状态、成品预览和入口。

## 通用经验更新规则

- 始终维护同一个 Skill，不设置人为版本号。
- 只有确认能够跨不同 Logo 案例复用的规则，才更新本 Skill。
- 单个案例的元素、视觉特征、修正细节和偶发现象，只记录在对应案例目录，不写入本 Skill。
- 新经验应保持简短、可执行，并放入最相关的现有章节。
- 不为尚未出现的需求提前增加分类、复杂结构、脚本或资源目录。
- 每次更新后运行 Skill 校验，确保 frontmatter、目录和元数据仍然有效。
