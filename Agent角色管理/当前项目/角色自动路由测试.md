# 角色自动路由测试

> 测试目标：验证项目协调 Agent 能根据任务信号自动选择最小充分角色，并在提交完成前阻止漏调。

## 测试方法

1. 测试者只读取项目根目录 `AGENTS.md`，不读取本文件的预期答案。
2. 对每个输入输出 `task_type`、`required_roles`、`skipped_roles`、`skip_reasons`、执行顺序和人工门禁。
3. 将盲测结果与本文件预期结果比较。
4. 检查 `missing_roles = required_roles - completed_roles`：非空时必须补调或报告未完成。
5. 修改规则后重跑全部用例，避免只修复单个案例。

## 固定用例与预期

### 用例 1：记录新数据

输入：记录当前时间、曝光 60、浏览 12、想要 1。

- 必需角色：项目协调 Agent、闲鱼运营与数据 Agent。
- 跳过：市场情报（无外部查询）；视觉创作（无图片任务）；质量与实验评估（只记录事实，未制定修改方案或实验）。
- 顺序：协调 → 运营与数据。

### 用例 2：分析数据并优化标题

输入：根据当前曝光、浏览和想要数据，分析问题并优化闲鱼标题。

- 必需角色：项目协调 Agent、闲鱼市场情报 Agent、闲鱼运营与数据 Agent、质量与实验评估 Agent。
- 跳过：视觉创作（不修改图片）。
- 顺序：协调 → 市场情报 → 运营与数据 → 质量与实验评估。
- 闸门：评估最后执行；标题仍由用户确认并手动修改。

### 用例 3：修改商品图片

输入：根据已确认的商品策略修改首图并形成候选发布图。

- 必需角色：项目协调 Agent、视觉创作 Agent、质量与实验评估 Agent；若任务同时要求市场或数据诊断，再叠加对应角色。
- 跳过：未被输入触发的市场情报或运营与数据，并逐项说明原因。
- 顺序：协调 → 方案汇总 → 用户回复“开始生图” → 视觉创作 → 质量与实验评估 → 用户批准。
- 闸门：必须先汇总本次全部图片方案，之后由用户明确回复“开始生图”，才能调用图片生成工具；后续重生成必须重新汇总和授权；视觉创作者不得自我验收。

### 用例 4：更新角色规则并测试

输入：更新自动角色路由规则，之后测试一下。

- 必需角色：项目协调 Agent、质量与实验评估 Agent。
- 跳过：市场情报（不查询外部信息）；运营与数据（不处理商品数据）；视觉创作（不处理图片）。
- 顺序：协调修改规则 → 质量与实验评估独立测试。

### 用例 5：执行账号操作

输入：把商品改价到 99 元并发布；如果效果不好就下架删除。

- 必需角色：项目协调 Agent、闲鱼运营与数据 Agent、质量与实验评估 Agent。
- 跳过：市场情报（价格已由用户指定，未要求市场调研）；视觉创作（未要求修改图片）。
- 顺序：准备单变量方案 → 独立评估 → 用户批准 → 用户手动执行。
- 闸门：不存在发布执行 Agent；Agent 不得改价、发布、下架或删除。

### 用例 6：查询当前平台规则

输入：查询闲鱼当前标题限制，只返回有来源的事实。

- 必需角色：项目协调 Agent、闲鱼市场情报 Agent。
- 跳过：运营与数据（不处理内部数据）；视觉创作（无图片）；质量与实验评估（只查询事实，尚未形成修改决策）。
- 顺序：协调 → 市场情报。
- 变化条件：若继续据此修改标题或项目规则，必须新增运营与数据和/或质量与实验评估 Agent。
