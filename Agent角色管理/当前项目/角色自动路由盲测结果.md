## 用例 1：记录新数据

- `task_type`：内部商品数据记录。
- `required_roles`：项目协调 Agent、闲鱼运营与数据 Agent。
- `skipped_roles`：市场情报（无外部调研）；视觉创作（无视觉任务）；质量评估（只记录事实，无方案或实验）。
- 执行顺序：项目协调明确口径和时间 → 运营与数据记录指标 → 项目协调汇总。
- 人工门禁：无。

## 用例 2：分析数据并优化标题

- `task_type`：基于内部数据的标题优化方案。
- `required_roles`：项目协调 Agent、闲鱼市场情报 Agent、闲鱼运营与数据 Agent、质量与实验评估 Agent。
- `skipped_roles`：视觉创作（不涉及图片）。
- 执行顺序：项目协调 → 市场情报 → 运营与数据 → 形成候选标题 → 质量与实验评估独立检查 → 项目协调汇总。
- 人工门禁：线上标题由用户确认并手动修改。

## 用例 3：修改商品图片

- `task_type`：商品首图编辑与候选发布图生产。
- `required_roles`：项目协调 Agent、视觉创作 Agent、质量与实验评估 Agent。
- `skipped_roles`：市场情报（策略已确认，无新增外部调研）；运营与数据（不读取或分析内部数据）。
- 执行顺序：项目协调确认策略和不变量 → 视觉创作汇总本次全部图片方案 → 用户明确回复“开始生图” → 视觉创作生产 → 质量与实验评估独立检查 → 项目协调提交通过的候选图。
- 人工门禁：方案汇总后取得当次生图授权；后续重生成重新授权；真正发布仍由用户批准并手动执行。

## 用例 4：更新角色规则并测试

- `task_type`：角色与流程规则更新及验证。
- `required_roles`：项目协调 Agent、质量与实验评估 Agent。
- `skipped_roles`：市场情报（无外部事实）；运营与数据（无商品数据）；视觉创作（无视觉素材）。
- 执行顺序：项目协调明确范围并更新规则 → 质量与实验评估在生产后独立测试 → `Needs work` 时返工并复验。
- 人工门禁：用户已用“开始更新”批准本次规则修改。

## 用例 5：执行账号操作

- `task_type`：线上改价发布与条件式下架删除实验。
- `required_roles`：项目协调 Agent、闲鱼运营与数据 Agent、质量与实验评估 Agent。
- `skipped_roles`：市场情报（99 元已由用户指定，无市场价格调研）；视觉创作（不涉及图片）。
- 执行顺序：项目协调定义权限边界 → 运营与数据定义起点、观察窗口和停止条件 → 质量与实验评估独立检查 → 用户批准并手动改价、发布 → 到达停止条件后重新请求用户决策。
- 人工门禁：改价、发布、下架和删除均由用户分别批准并手动执行，不能自动触发。

## 用例 6：查询当前平台规则

- `task_type`：纯外部时效性平台规则查询。
- `required_roles`：项目协调 Agent、闲鱼市场情报 Agent。
- `skipped_roles`：运营与数据（无内部数据）；视觉创作（无图片）；质量评估（只查询事实，不改变项目方案）。
- 执行顺序：项目协调限定查询范围 → 市场情报保留来源、时间和不确定性 → 项目协调汇总有来源的事实。
- 人工门禁：无。

## 完成闸门检查

六个用例均声明：

```text
missing_roles = required_roles - completed_roles
```

只要 `missing_roles` 非空，就补调缺失角色；无法补调时报告未完成。包含质量评估的用例 2、3、4、5 均把评估放在生产之后，测试者和质量评估者均未参与规则生产。
