## Problem Statement

项目已经积累了图片生成偏航和角色漏调等已验证失败，但事实分散在案例记录、测试记录和流程文档中。Agent 开始任务时缺少一个按作用域可搜索的入口，可能重复已证明无效的动作，或者为了寻找恢复路径而读取失败 Prompt、失败图片和完整实验流水。规则也缺少统一的写入前作用域判断，容易把案例事实上浮为通用规则，或把通用规则重复写入多个层级。

## Solution

建立一套最小充分的分层失败知识体系：通用执行约束负责规则作用域和已验证失败的强制动作；项目工作台负责导航；每个独立失败条目以六个原子条款保存触发、停止和恢复规则；适用 Skill 在流程节点引用条目，不复制正文；案例与测试记录只保存事实证据。失败生产素材进入明确禁止生产读取的隔离归档，保留内容哈希、历史路径和复现入口。

## User Stories

1. 作为项目协调 Agent，我想在实质工作前检查当前范围的已验证失败知识，以便避免重复已知错误。
2. 作为规则维护者，我想在写入规则前判断完整适用范围，以便把规则放在正确层级。
3. 作为规则维护者，我想让依赖下层上下文的规则留在下层，以便避免案例细节污染通用规则。
4. 作为项目 Agent，我想通过一个简洁工作台搜索失败 ID、领域和触发摘要，以便只打开命中的条目。
5. 作为项目 Agent，我想让每个失败文件只描述一个失败模式，以便理解触发和恢复路径时不受其他实验干扰。
6. 作为项目 Agent，我想在命中触发条件时立即停止指定路径，以便不扩大已知损失。
7. 作为项目 Agent，我想禁止重复适用条件未变化的无效动作，以便不把重试误当作修正。
8. 作为项目 Agent，我想只执行条目确认过的恢复路径，以便在失败后可预测地继续。
9. 作为项目 Agent，我想在恢复或验收条件未满足时报告阻断，以便不虚报完成。
10. 作为 Logo 任务执行者，我想在源资产预检和修正分流时看到精确不变量失败入口，以便在正确节点停止全图生成修正。
11. 作为 Logo 任务执行者，我想让通用修正 Prompt 明确排除精确不变量偏差，以便不会误用全图修正模板。
12. 作为生产 Agent，我想无需读取失败 Prompt、失败图片或完整案例记录就能执行恢复规则，以便避免把失败素材当作模板。
13. 作为资产维护者，我想把失败测试素材移入隔离归档并保留稳定路径与哈希，以便维持审计和复现能力。
14. 作为资产维护者，我想保留实际执行时的历史路径和命令原文，以便迁移归档不会改写历史事实。
15. 作为质量评估者，我想只依据通用规则、项目入口、命中条目和适用 Skill 做盲测，以便验证知识路由不依赖案例答案泄漏。
16. 作为审查者，我想分别检查仓库规范和本 Spec，以便标准合规与需求覆盖不会互相掩盖。

## Implementation Decisions

1. 通用层新增两个并列约束组：规则作用域、已验证失败处理；两组都采用编号、原子条款，不包含当前项目路径、Logo 案例或工具细节。
2. 项目层采用“一个工作台 + 一个失败一个文件”。工作台仅保存 ID、领域、触发摘要、必须停止、状态和条目链接。
3. 每个失败条目正文固定为“适用、触发、停止、禁止、恢复、通过”六个编号条款；证据和状态置于末尾。
4. 首批只收录已有直接事实证据的图片精确不变量偏航和生产者自检替代独立评估。数据小样本和历史字段推测目前没有已验证错误事件，不创建预设条目。
5. Skill 只在源资产预检、精确不变量分流和通用修正入口引用项目失败条目，不复制条目正文，也不保存案例过程。
6. 通用修正 Prompt 显式声明不适用于锁定画布、背景、有限调色板、边界、位置、尺寸或间距等精确不变量偏差。
7. 二次开发 Prompt 保留授权编辑区域和锁定不变量契约，作为生成前的正确生产方法；它不保存失败过程或恢复规则。
8. 失败图片、原始生成源和失败 Prompt 移入案例内的测试隔离归档。归档入口明确禁止生产任务读取，仅允许溯源、审计、复现和专门测试。
9. 采用隔离归档而非删除，因为测试素材当前未进入 Git，删除无法依靠 Git 历史恢复；隔离归档保留 v3 的直接输入和 SHA-256。
10. 历史实际命令和执行时路径保持原文；资产清单补充归档后稳定路径和迁移说明，不把后续路径改写成执行时事实。
11. Prompt 生产索引不再直接暴露失败 Prompt；只保留生产 Prompt，并引用生成记录作为历史事实入口。
12. 本改动是一条可在单次会话完成并验证的垂直切片，不拆本地 Ticket。

## Testing Decisions

1. 最高层测试 seam 是独立 Agent 盲测：只提供通用规则、项目失败工作台、命中条目和适用 Skill，不提供杨荣洋案例、失败 Prompt、失败图片或预期答案。
2. 盲测必须证明 Agent 能把通用规则、项目规则、Skill 规则和单次事实路由到正确层级。
3. 盲测必须证明精确不变量偏差会停止全图生成修正，并选择授权区域内的局部或确定性恢复路径。
4. 盲测必须证明失败 Prompt 不被当作可复用模板，且无需读取案例即可给出正确分流。
5. 使用确定性检查验证 Markdown 链接目标存在、失败工作台字段完整、每个失败条目恰有六个规则条款、生产索引不再引用失败 Prompt、归档文件哈希不变。
6. 使用 Skill 校验器验证 frontmatter、命名和目录结构；使用 Markdown 与 Git 差分检查验证格式。
7. 最终审查固定点为本 Goal 开始前的基线提交 `e2a4cb472b0602fa5aae1dc59dca6472ffb9a192`；Standards 轴依据仓库规范和 Fowler smell baseline，Spec 轴依据本 Spec，二者由独立 Agent 并行执行。

## Out of Scope

1. 不调用图片生成工具或重新生成 Logo。
2. 不建立没有直接事实证据的错误百科。
3. 不修改现有角色体系或账号权限边界。
4. 不操作远程 Issue Tracker。
5. 不把失败 Prompt、失败图片或完整实验流水复制进失败知识条目。
6. 不回滚、覆盖或提交共享 worktree 中本 Goal 之外的既有改动。

## Further Notes

1. 项目失败知识是生产方法入口；案例和测试记录仍是事实证据的单一来源。
2. 新失败条目必须先有可引用的实际证据，再按相同结构追加。
3. 隔离归档改变当前稳定路径，但不改变文件内容、SHA-256、执行时路径或历史命令。
