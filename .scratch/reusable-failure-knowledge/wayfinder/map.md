# 建立可复用失败知识与 Agent 防偏航机制

## Destination

形成一份可以直接交给 `$to-spec` 和 `$implement` 的完整决策输入。

最终系统必须让 Agent 根据任务范围找到适用的已验证失败知识，在命中触发条件后停止已知错误路径，并执行经过确认的恢复路径，而无需读取失败案例全文。

## Notes

- 本 Goal 只使用本地 Markdown，不操作远程 Issue Tracker。
- 遵循最小充分原则、不变量驱动、条款化和原子化。
- Agent 能否稳定理解和执行是主要验收标准。
- 通用规则、项目规则、Skill 规则和案例事实必须按作用域分层。
- 失败知识只收录有实际证据的失败，不建立假设性错误百科。
- 主 Agent 负责主流程、决策、集成和最终交付。
- 可使用子 Agent 执行独立盘点、盲测和双轴审查。
- 不调用图片生成工具，不重新生成 Logo。

## Decisions so far

- [规则作用域如何分层](./decisions/01-规则作用域如何分层.md)
  — 写入规则前先判断完整适用范围；依赖下层上下文的规则不得上浮。
- [Agent 命中已验证失败后如何行动](./decisions/02-Agent命中已验证失败后如何行动.md)
  — 命中后立即停止，不重复已验证无效动作，只执行恢复路径，未恢复不得完成。
- [失败知识如何组织](./decisions/03-失败知识如何组织.md)
  — 使用一个工作台和一个失败一个文件；工作台只索引，条目保持原子化。
- [失败条目采用什么结构](./decisions/04-失败条目采用什么结构.md)
  — 每条固定包含适用、触发、停止、禁止、恢复、通过六个原子条款。
- [AGENTS、项目规范、Skill 与案例如何分工](./decisions/05-资料职责如何分工.md)
  — AGENTS 定义通用行为，项目规范保存失败知识，Skill 引用条目，案例只保存证据。
- [recreate-logo 如何接入失败知识](./decisions/06-recreate-logo如何接入失败知识.md)
  — 在预检和修正分流处引用图片失败条目；精确不变量失败后不得进入全图生成修正。
- [首批建立哪些失败条目](./decisions/07-首批建立哪些失败条目.md)
  — 只建立有实际失败证据的图片条目和角色评估条目；不为目录完整性创建无证据条目。
- [测试候选如何退出生产资料](./decisions/08-测试候选如何退出生产资料.md)
  — 将仍承担血缘证据的失败候选移入非权威隔离归档；从生产索引和正常读取入口移除，不直接删除不可替代证据。

## Out of scope

- 重新执行 Logo 图片生成。
- 建立覆盖所有可能错误的错误百科。
- 收录没有实际失败证据的条目。
- 修改现有角色体系。
- 操作远程 Issue Tracker。
- 回滚或覆盖当前 worktree 的既有改动。
- 把失败 Prompt 或失败图片重新提升为生产参考。
- 修改与本 Goal 无关的项目资料。
