# 资产溯源与派生血缘及 Logo 二次开发 Spec

## Problem Statement

项目已有 Logo 复刻和二次开发资产，但通用规则、`recreate-logo` 流程与案例记录尚未使用同一套血缘语义。当前记录无法稳定回答资产来自哪里、以什么模式派生、实际经过哪些 Prompt/工具/后处理、如何验证，也没有明确保护历史调用事实不被回写。

## Solution

建立一套最小充分的资产溯源与派生血缘约束：根目录 `AGENTS.md` 只保存核心不变量和执行入口，详细字段、模板与示例集中在项目规范中；`recreate-logo` 在生图前判定“复刻”或“二次开发”，把“修正”保留为两种模式共用的质量循环；杨荣洋案例用单一生成记录完整表达实际资产链和历史边界。

## User Stories

1. 作为项目协调 Agent，我希望任何派生资产都能追溯根权威参考、直接输入、输出、变换和验证，以便判断资产身份与来源。
2. 作为资产生产者，我希望在执行前判定复刻或二次开发，以便选择正确的权威关系和 Prompt。
3. 作为资产生产者，我希望合格源资产能直接作为输入，以便避免无意义的重新生成。
4. 作为质量评估者，我希望修正被记录为所属任务模式中的新版本，以便保留完整返工历史。
5. 作为维护者，我希望历史 Prompt、调用、变换和结果不可变，以便后续审计基于实际事实。
6. 作为维护者，我希望每项来源或变换事实只有一个完整权威记录，以便避免多处副本发生冲突。
7. 作为案例阅读者，我希望只读杨荣洋生成记录就能理解完整资产链，以便无需跨案例自行拼接。

## Implementation Decisions

1. 顶层任务模式只有“复刻”和“二次开发”；修正是两种模式都可进入的质量返工循环，不是第三种模式。
2. 模式由输出资产身份决定：同一参考 Logo 的首次还原属于复刻；保留已有资产部分特征并形成新文字、品牌、版式或用途资产属于二次开发。
3. 二次开发由根权威参考、直接父资产和用户确认的变更规格共同约束；直接父资产不得被输出覆盖。
4. 资产记录包含资产身份、根权威参考、直接输入资产 `1..N`、输出资产、派生关系、实际 Prompt、工具、模型、执行 ID、后处理、规格、SHA-256 与验证生命周期。
5. 根目录规则只定义不变量、术语与执行要求；详细字段、格式、模板和示例只在项目资产管理规范完整维护。
6. Skill 新增二次开发 Prompt 参考；Prompt 使用根权威参考、直接父资产、实际编辑目标、用户新内容、保持项、改变项和输出规格，不包含单案例文字、颜色、尺寸或哈希。
7. 杨荣洋案例的两份实际调用 Prompt 正文保持不变。首稿正文 SHA-256 基线为 `ad3db3f815d77df5a3a9677d1a40241e96d9def5e00ba8a608798580aae0b86e`；修正正文基线为 `cb6d0b6931b8720c73bc37dc32bd94efa8250f8858a61d3eb2a45e763947714c`。
8. 杨荣洋实际输入已是 `1200 x 1200 PNG`。首稿 Prompt 中 `2048 x 2048` 到 `1200 x 1200` 的表述仅作为历史原文保留，生成记录追加说明本次执行未发生该输入缩放。
9. 不增加生产代码或复杂自动化；现有系统 Skill 校验脚本、链接检查、字段检查、图像规格与哈希检查足以覆盖风险。
10. 工作量可在一个上下文内完成，文件间依赖简单，因此直接实现，不拆本地 Ticket。`grill-with-docs` 和 `wayfinder` 无需调用，因为领域决策、术语、范围和验收标准均已确认。
11. Skill 当前实际表现只覆盖唯一参考复刻和修正，无法表达二次开发的模式判定、三类权威关系、源资产预检与派生归档；预期表现是同时支持复刻和二次开发，并保持既有授权门及修正循环。修复范围限于新增模式判定、源资产预检、二次开发 Prompt 引用和资产管理归档，不改变已有生图权限流程。

## Testing Decisions

1. 采用一个最高层文档/Skill 合约 seam：同时验证 Skill 格式、文档链接、关键章节与字段、案例完整性、PNG 规格与 SHA-256、历史 Prompt 正文不变性。
2. 使用 `quick_validate.py` 验证 Skill frontmatter、命名和目录结构。
3. 使用仓库级脚本化只读命令验证 Markdown 链接目标存在，通用 Skill 不包含单案例内容，杨荣洋记录包含完整资产链字段。
4. 使用 `sips` 与 `shasum` 验证资产规格和哈希；不重新生成或改写任何图像。
5. 对启动基线后的 diff 分别执行 Standards 与 Spec 双轴审查；发现阻断项后修正并重新审查。

## Out of Scope

- 重新生图、修改或覆盖现有 PNG。
- 改写历史实际 Prompt 正文、工具调用、执行 ID 或变换结果。
- 修改系统 `imagegen` Skill。
- 新增生产代码、数据库或复杂血缘自动化。
- 修改角色、自动路由、用户批准门或 `当前角色与流程.md`。
- 创建或操作任何远程 Issue、PR 或账号。
- 发布、改价、删除或下架闲鱼商品。

## Further Notes

- 详细规范位于 `项目规范/资产管理/资产溯源与派生血缘.md`。
- 启动时工作树已有 `.gitignore`、阿川家案例文件与 PNG 的用户改动，以及未跟踪的杨荣洋案例。本实现不回滚这些改动；提交时只暂存本 Spec、通用规则、详细规范、Skill 变更、杨荣洋案例，以及用于保存实际直接父资产内容且不覆盖历史路径的阿川家黄底文字版 `1200 x 1200` 版本化快照。启动前原路径改动和 `.gitignore` 不纳入本 Goal。
